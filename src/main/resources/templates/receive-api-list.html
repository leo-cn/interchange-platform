为什么接口要先登记
平台的接收端点只有一条：POST /api/receive/{apiCode}， apiCode 是 URL 上的一段。以前这一段不需要任何注册 —— 第三方调一个你根本没写过的编码也会被返回「接收成功」， 因为没有专门处理逻辑时会走兜底回执。排查问题时极易误判成"接口已经通了"。
登记之后：未登记或已停用的接口会被直接拒绝（401 接口未定义）， 不再静默成功；同时「接口令牌」页给接入方授权时，可以直接勾选这些接口， 不用手敲字符串，避免拼错导致对方 401 却查不出原因。
变更有最长 60 秒的生效延迟（服务端有缓存）。需要立刻止损时， 用「停用接入方」或「注销令牌」更快，那两项是实时的。
第三方怎么调
curl -X POST http://127.0.0.1:18080/api/receive/order-receive \
  -H "Content-Type: application/json" -H "X-Token: AT-…" -d '{"bizNo":"A001"}'
X-Token 里的令牌要先用 appKey / appSecret 到 /api/oauth/token 换 —— 凭证在「接口令牌」页管理。
免鉴权只建议留给内网健康检查这类接口；对外业务接口一律要求令牌。
